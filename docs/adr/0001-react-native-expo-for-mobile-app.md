# React Native (Expo) for the Mobile App, not native Swift

`PROJECT.md` had deferred native mobile apps entirely; we're now building one, iOS first with Android as a committed near-term follow-on, and the obvious instinct for an "iOS app" is native Swift/SwiftUI. We chose **React Native via Expo** instead, living in this monorepo at `apps/mobile`. The developer is solo with strong React/TypeScript and no deep Swift experience, Android is coming soon enough that a second native codebase would be wasted work, and Expo's managed workflow (EAS Build/Submit) keeps iOS builds and TestFlight submission tractable without a heavy native toolchain. This also lets the Mobile App import `@neighborhood-connect/types` directly and reuse the existing Turborepo/pnpm tooling. Capacitor (wrapping the existing Vite SPA) and Flutter were considered and rejected: Capacitor gives a weaker native feel and awkward push-notification integration; Flutter would abandon the React skill and type-sharing advantage for no offsetting benefit here.
