# Expo Push Notification Service over AWS SNS Mobile Push

`docs/aws-architecture.md` establishes an AWS-first hosting philosophy, which would point toward AWS SNS Mobile Push with direct APNs integration for delivering push notifications to the Mobile App. We chose **Expo's Push Notification service** instead: the Mobile App registers an Expo push token (not a raw APNs device token) with the backend, and the API calls Expo's single push API rather than managing APNs signing keys and certificates directly. This is a deliberate deviation from the AWS-first default, made because the operational cost of self-managing APNs credentials falls entirely on a solo developer, and Expo's service delivers to both iOS and Android through one API once the Android build ships. The trade-off: push delivery now depends on Expo's infrastructure rather than AWS end-to-end; this can be swapped for direct SNS/APNs later without changing how the backend stores Device Tokens, since the registration record would just change what kind of token it holds.
